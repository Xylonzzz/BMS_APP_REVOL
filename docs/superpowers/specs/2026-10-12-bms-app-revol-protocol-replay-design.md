# BMS_APP_REVOL 协议与回放质量基线设计

日期：2026-10-12
状态：已获用户确认，待实施计划

## 目标

为 BMS_APP_REVOL 建立可追溯、可回放的协议与质量状态基线，贯通协议解码、不可变会话记录、只读 API 和浏览器证据展示，为后续 Windows MVP 提供稳定合同。

## 范围

本阶段只处理只读数据链：模拟或回放 CAN 帧、协议解析、质量判断、快照与诊断事件、API 查询和浏览器展示。暂不接入真实 CAN、ST-Link、高压设备、继电器/充电控制、Android 原生硬件、小程序构建和服务器同步。

## 数据与合同设计

`CanFrame` 保留总线、方向、ID、IDE/RTR、DLC、原始数据、采集时间和序号。协议字典按总线与方向区分同一 ID 的不同含义，并记录解析规则版本。

每个解析值使用统一质量字段：`valid`、`quality`、`timestamp`、`sequence`、`source` 和 `rawFrameIds`。质量状态至少包含 `valid`、`pec_error`、`timeout`、`partial`、`stale`、`range_error` 和断线状态。保留原始数值不等于采样有效；页面和 Agent 必须依据质量状态判断。

144 个软件电压槽与 136 个物理电芯保持兼容边界。协议层可以保留空槽，但必须标明物理有效性，不能把槽位数量直接当作物理电芯数量。AF/EF 识别先输出证据和候选结果，不在本阶段自动改变数据含义。

## 回放场景

建立固定、可重复的 JSONL 场景：

1. 全部有效帧和连续序号。
2. 单帧 PEC 错误：保留原始值，解析值无效，并生成诊断事件。
3. 缺帧或短帧：标记 `partial`，不凭空填充缺失字段。
4. 超时：超过场景阈值后生成 `timeout`，并保留最后值为 `stale` 或明确旧值状态。
5. 部分更新：只更新收到的槽位，未更新槽位保留旧值并有序号/时间证据。
6. 断线与重连：断线期间不生成“新鲜有效”快照，重连后序号重新建立连续性。

## 数据流

```text
回放 JSONL
  → CanFrame 校验
  → 协议解码
  → 质量判断与诊断规则
  → BmsSnapshot / DiagnosticEvent
  → 不可变 SessionStore
  → API
  → 浏览器原始帧、解析值、质量状态和诊断证据
```

API 只读返回快照、帧引用、诊断事件和回放元数据。客户端不复制协议规则，不根据页面数字自行推断有效性。

## 错误处理

输入帧格式错误、DLC 不匹配、未知方向或未知规则版本必须返回结构化错误或 `unknown` 状态，不能静默按普通有效值处理。会话记录追加失败时 API 返回明确错误，不丢弃已存在的不可变记录。回放场景必须能单独运行，错误不会污染后续场景。

## 验证

- Python 单元测试覆盖所有回放场景、质量状态、原始帧引用和不可变追加。
- Schema 校验覆盖新增字段和枚举。
- API 测试验证快照、诊断、质量和回放元数据可查询。
- 浏览器检查验证有效值、无效值、旧值、断线和恢复状态的视觉语义。
- 明确记录未连接真实 CAN、未完成服务器部署和未完成多端打包，因此不作对应平台验收结论。

## 后续边界

本阶段完成后，下一阶段才设计 Windows Tauri MVP：复用本阶段合同与回放验证，增加本地 Edge Agent 适配器和桌面壳，不改变质量语义和只读安全边界。

## 旧上位机功能兼容基线

新平台保留旧上位机的用户可见功能语义作为兼容基线：BMS 状态、单体电压、单体温度、继电器/充电状态、阈值、CAN 收发、诊断与测试入口。页面名称、关键单位和 AF/EF 分区保持可识别；控制入口在只读阶段显示为未实现或回放状态，不伪造控制闭环。

### AF/EF 自动识别

旧上位机的实现事实如下：

- DATA.Model 使用 1=AF、2=EF，首页标题和 AF/EF 电压、温度页面根据它切换。
- 自动模式检查每个模组边界电压槽（17, 35, ... , 125）以及温度槽 48..69 的零值特征。
- 测试页可以手动选择 AF 或 EF，手动选择优先于自动判断。
- AF/EF 还会影响断线检查的遍历数量和页面展示数量；不能只替换首页标题。

旧实现存在需要修正的边界：逐个槽位更新标志会覆盖前一次结果，数据尚未收齐时也立即决策，混合证据默认偏向 EF；部分扩展帧还会直接把型号设为 EF。这些行为只作为兼容证据保存，不直接复制到新平台。

新平台的 ModelDetection 结果至少包含：

model: af | ef | unknown
mode: automatic | manual
confidence: high | medium | low
reason: 触发判断的槽位、帧、时间和规则版本
observed: 当前已收齐/缺失的电压与温度特征

自动识别只有在所需证据达到收齐条件、序号连续且数据未超时/未标记为旧值时才更新稳定型号；证据不足时保持 unknown 或上一稳定型号并明确原因。手动 AF/EF 选择作为用户配置记录，必须显示覆盖来源和时间。识别结果不能改变原始帧、解析值和质量状态。

### 兼容验证

回放测试至少覆盖：

1. AF 特征完整收齐后切换为 AF。
2. EF 特征完整收齐后切换为 EF。
3. 混合、缺帧、旧值、PEC 错误和断线期间保持 unknown 或上一稳定型号，不静默改成 EF。
4. 手动 AF/EF 覆盖自动结果，并能恢复自动模式。
5. 型号变化同步影响电压页、温度页、断线统计和首页状态，但不改变原始数据。
