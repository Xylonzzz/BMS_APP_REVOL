# REVOL 首轮真实 CAN 只读联调

软件具备 ControlCAN 接收、原帧记录、逐字段聚合、监控、回放及导出。本文是待执行的现场步骤，当前没有真实设备验收结果。2026-10-13 用户确认可以参考旧上位机，手头适配器与板内固件版本尚待确认。

## 已核对的兼容参数

| 项目 | 旧上位机证据与 REVOL 初始值 |
| --- | --- |
| SDK | `ControlCAN.dll`，`VCI_OpenDevice/InitCAN/StartCAN/Receive/CloseDevice` |
| 设备 | 类型 `4`（旧代码注释 `USBCAN2`），设备索引 `0`，通道 `0` |
| 波特率 | 默认 `500000`，Timing0/1=`00/1C`；另支持 `250000`=`01/1C` |
| 协议 | 活动 BMS 的 CAN1 标准数据帧，小端，正常 DLC=8 |
| 工作模式 | REVOL 使用 Mode=1 只听，不发送数据或 ACK；旧程序默认 Mode=0 收发 |
| 固件 | 本次协议对照源码 HEAD `42d4433`；不能据此认定板内也是此版本 |

旧源码位置：`D:\BMS\上位机仓库\BMS_App\BMS_App\CAN.cs`，设备默认在149–153行，通道/波特率默认在166–171行，时序和Mode配置在404–418行。设备名 USBCAN2 不等于连接主控 CAN2。

已只读检查 DLL PE 头：旧源码 `bin/Debug/ControlCAN.dll` 为32位，`D:\BMS\BMS_App_10.1\BMS_App_10.1\ControlCAN.dll` 为64位。当前发布包为64位，后者仅在位数上匹配；厂商来源、驱动和具体设备兼容性尚未验证。不要把另一个目录的 DLL 覆盖原工程文件；在启动器中选择对应 SDK 路径。

## 第一轮操作与验收

1. 用户确认适配器型号、驱动、实际连接的主控 CAN1、波特率和板内固件标签。接线、台架状态及实物操作由用户完成；本轮不修改或烧录固件。
2. 选择“只读 CAN”，核对设备类型/设备索引/通道/波特率和匹配位数的 DLL，点击启动。启动页应给出会话目录与接收状态；错误须保留完整提示。旧上位机先释放同一适配器，避免两个进程抢占驱动。
3. 在 CAN 页面确认接收帧数量持续增加，检查实际 ID、DLC、IDE/RTR 和时间。只听不发送 ACK，现场总线上需已有正常应答节点；若只有 BMS 与监听器两节点而收帧异常，先核实 ACK 条件，不能把该现象直接归为解析错误。
4. 在总览核对 `0x100`：B0–3 有符号 mA → A；B4–5 为累压0.1V；B6–7为ADC总压0.1V。核对 `0x101`：B0–1预充0.1V；B2–3 SOC 0.1%；B7是Init_flag，不是告警等级。用同一记录的原始帧核算，避免比较不同时间的画面。
5. 核对单体电压 `0x104–0x127` 的144软件槽，按8模组分隔；每组第18槽为兼容保留槽，136物理电芯。核对温度 `0x128–0x133` 的48通道；8×6是软件组织，探头物理位置仍需现场映射。
6. 核对继电器反馈 `0x139`、充电机 `0x140`、告警 `0x141–0x143`。预充状态镜像不证明实物触点动作。阈值 `0x150–0x15D` 未收到时保持空；REVOL 本版不会发送阈值读取/写入命令。
7. 连续记录一段现场会话后点击停止，确认采集和服务退出；重新启动后从记录库打开旧会话，逐步回放并导出 CSV、完整 ZIP。核对 ZIP manifest、原帧及快照存在，停止前后最后接收时间一致。

真实协议尚无逐槽PEC、固件采样批次/采样时间，因此页面的 unknown/有效性待确认是预期表现。主机接收时间与序号只能证明接收顺序；不能因为各项显示数字就改成 valid。需要验证超时或恢复时，由用户控制台架连接，观察保留旧值的时间/质量是否变化，原记录不得删除或改写。
