# Web客户端

启动 API 后，在项目根目录运行静态服务器：

```powershell
python -m http.server 4173 --bind 127.0.0.1 --directory apps/web
```

浏览器打开 `http://127.0.0.1:4173`，页面默认读取 `http://127.0.0.1:8765`。默认陶瓷白，支持深海蓝与雾蓝外观；PEC 错误单体保留数值并使用红色无效状态显示。

顶部“加载回放”可以加载 `valid`、`pec_error`、`partial`、`timeout_stale`、`disconnected_reconnect`、`af`、`ef` 和 `mixed_model` 场景；“连接设置”包含 API 地址与 AF/EF 手动覆盖。页面显示自动/手动来源和识别原因。

加载回放从第一条开始，使用上一条/下一条查看记录时间和序号。断线重连含三个步骤；失败后保留旧值但明确失联。自动/手动切换不修改原始快照；辅助分析仅针对 API 最新快照，回放中禁用。页面按 API 区分模拟、CAN 接收和离线文件；软件支持接入不代表实物联调已经通过。默认最新快照每秒刷新，回放期间暂停。

回归验证：`node --test apps/web/test_app.cjs apps/web/test_modules.cjs apps/web/test_product.cjs`。

总览顶部独立显示电池总压（ADC）、单体累压、预充电压（独立ADC）、整包电流和SOC，单位为V/A/%。新版模拟状态报文0x100/0x101与卡片一一对应，正常共38帧。历史记录未包含这些状态帧时，缺失测点显示“未接入”；原totalVoltage仅作为mV槽位计算累压转换为V，不能替代ADC总压或预充。断线卡片保留原值与采样时间，并标为旧值。悬停卡片可查看来源、时间、序号与原始帧引用。

界面采用电池工作台布局：左侧导航、中间模组地图或单体托盘、右侧单体详情与本批次证据。总览点击“查看全部单体”展开各模组；每组显示有效范围、有效压差、有效数量及保留槽。数量由 `moduleIndex` 决定，兼容已知历史 `slave_XX` / `simulated_slave_XX` 来源；无法确定的来源显示未分组，不按槽位数量猜测拓扑。

点击单体可查看原始质量、记录时间、序号、来源及帧引用，回放换步后详情同步更新。有效统计排除保留槽、无效值和非有限数值；API 失联或设备断线时不输出有效范围/压差，保留原值。外观、密度与动效偏好不改变质量语义。手机布局自动改为单列模组与三列电芯，证据区在下方。

左侧导航参考旧上位机的 `BMS_STATE`、`Cell_Vol_1/2`、`Cell_Tem_1/2`、`realy_charge`、`Threshold_Value1`、`CAN` 和 `Test_Control` 页面。页面语义兼容旧软件，但不复制旧软件中未经验证的控制闭环。

温度页按固件索引显示 8 个软件模组，每组 GPIO1–6，共 48 路；实物模组顺序与探头安装位置尚未确认。模拟器额外通道单列为模拟扩展，不计入真实固件 48 路。反馈页显示继电器、充电反馈/目标、BMS 状态与告警；继电器只解释 0/1，其他数值显示异常状态。阈值页只显示已收到的参数回读，不发送查询或写入；缺失值显示未收到。

A03 字段目录从 `/api/v1/catalog` 读取已传输字段，可按名称/路径搜索，展示工程值、质量、记录时间和原始帧引用。`signals` 按目录 divisor 换算，`packStatus` 已是工程单位，不再次除数。保留槽明确标为非物理电芯；`initFlag` 是阈值初始化标志，不作为告警等级。

记录库使用 `/api/v1/sessions` 和会话分页接口，每页最多 100 条；上一/下一条可以跨页，加载记录期间与回放期间不会被最新快照覆盖。趋势仅显示当前加载窗口，缺值断开，待确认/无效值使用虚线与空心点，不冒充有效采样。简易 CSV、完整 ZIP、最新快照 JSON 由 API 导出，保留原始记录。

显示偏好保存为本机 `bms-view-profile` v1 JSON：Minimal、Engineering、Operations 主题，以及密度、动效、自动刷新。支持导入、导出和恢复默认；导入只接受白名单 UI 字段，不改变质量判断。
